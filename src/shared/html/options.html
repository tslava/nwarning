Environment Warning Settings

Site access

The extension has no permission to run on the pages you visit, so the banner will never appear. Manifest V3 leaves this decision to you.

The browser would not ask. Grant access from the browser's own extension settings — in Firefox, the extension's entry in about:addons → Permissions; in Chrome, its card in chrome://extensions → Site access.

Environments

One production host, and every non-production host that mirrors it — dev, staging, QA — separated by commas. The banner appears on all of them, and switching moves you between any two hosts in the group.

Enter hostnames, not full URLs — a scheme, port or path is stripped automatically, so https://app.example.com/login is stored as app.example.com.

A * wildcard stands for exactly one label, so *.example.com matches app.example.com but not example.com or a.b.example.com — use *.*.example.com for two levels. Every host in a group must contain the same number of wildcards, so that whatever a wildcard matched is carried over when switching.

  • example.com → dev.example.com, staging.example.com
  • *.production.example.com → *.dev.example.com

Local Storage Variables Tracking

Watch specific localStorage keys of the visited page and show them in the banner, so a feature flag left switched on is visible at a glance.

Values of 1 or true are highlighted as switched on; anything else is shown dimmed. A key that is not set on the page gets a neutral chip that offers to set it: clicking writes the value chosen here and opens the page in a new tab, since such flags are read once at startup. A value outside 0/1 and true/false is never overwritten — that is somebody's configuration, and localStorage keeps nothing to undo a click from.

Hosts are ticked from the environment groups above. With none ticked the key applies everywhere the banner appears; ticking hosts limits it to those. The same key may be listed twice with different hosts and values — 0 on production and 1 on a stand, say — and the first row matching the page wins.

Example keys to track:

  • bestcompany-production-enabled
  • use-prod-database

Import / Export

Settings follow your browser profile automatically. Use this to hand a configuration to someone else, or to move one between profiles by hand.

Export writes the current configuration below; Download file saves it as JSON. Load file reads a file into the box without applying it, so you can look first — Import is what replaces the configuration. Imported data is validated exactly like the form above, and anything unusable is reported rather than quietly dropped. Whether the extension is switched on is not part of the payload.
